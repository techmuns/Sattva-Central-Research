# Continuous portfolio news

TradingView is additive public-headline discovery, not an exhaustive or guaranteed real-time stream.

- `tradingview-news-refresh.yml` targets minute 7, 22, 37 and 52 of every hour, seven days a week. An eight-minute collector budget and independent concurrency keep slow core/global searches out of its path. It starts from current `main`, not an older queued event SHA.
- Every run resolves the active portfolio. Newly verified exchange symbols enter the fair queue; exited holdings stop polling while their history remains archived. Failed portfolio verification retains the last known book and reports that new additions may be unknown.
- Requests are serial and spaced. A 401/403/429 stops the source-wide walk and persists backoff before reporting failure. No alternate accounts, regions, endpoints or subscription bypasses are used.
- Transient network/408/5xx reads get at most one retry with jitter inside one 15-second deadline. Longer `Retry-After` values defer the symbol to a later run; repeated failures back off from five minutes to one hour, and unsupported 404/422 symbols for a day. Exact HTTP errors remain recorded. Twenty-symbol checkpoints atomically save archive bytes before success watermarks, and restart ordering favors unattempted symbols. A later collector error can publish those saved checkpoints but still fails the final health gate.
- NSE membership is resolved from the actual NSE directory, not the merged directory's ticker field (which also contains BSE-only companies). Previously successful, independently identified historical NSE venues remain in the plan. Reviewed BSE spellings are [J_KBANK](https://in.tradingview.com/symbols/BSE-J_KBANK/), [M_M](https://in.tradingview.com/symbols/BSE-M_M/), and [M_MFIN](https://in.tradingview.com/symbols/BSE-M_MFIN/); their NSE ampersands remain unchanged. An unavailable venue does not remove the company from the portfolio or other news searches.
- Only `public/data/tradingview-news/` is published by this workflow. The portfolio checkpoint, monthly append-only archive, source checkpoints and recent `latest.json` share that isolated write set. The slower news workflow owns its original files. This avoids cross-workflow overwrites and serial queues behind long search walks. Initial migration copies previously archived TradingView observations without deleting the old archive.
- News, All Alerts and AI Alerts consume the same merged feed. One extra first-party snapshot is read alongside the original `news.json`. Open visible consumers revalidate the two snapshots every two minutes; there is no client-side company fan-out or automatic workflow dispatch. Hidden/unmounted readers stop polling, but server capture continues independently.
- Empty or failed reads preserve retained news. Source story IDs, canonical URLs and same-publisher headlines deduplicate within each company. Source timestamps and core-search timestamps remain distinct; a fresh TradingView capture cannot make a stale core search appear fresh.
- Capture and oldest successful symbol sweep become critical after 45 minutes. Failed/blocked reads, unavailable publication and unverified portfolio membership also need attention. Missing mappings, restricted headlines and possible bounded-window gaps remain explicit limitations.
- The collection workflow publishes partial progress before its health gate. The existing read-only `filings-health.yml` watchdog independently checks the deployed TradingView snapshot every half hour, even when another source-health step fails. GitHub failure notifications depend on operators' notification settings; no new email/Slack delivery is claimed.

## Limits and operations

`news-recovery.yml` adds a bounded catch-up check at minutes 3, 18, 33 and 48, plus completion events from the existing collectors and health check. It covers TradingView, Moneycontrol, the four RSS publishers, company/global/IR enrichment, X and Telegram. It runs without an open dashboard and starts only fixed incremental workflows on `main`; never a full scan, cancellation, rerun or deployment. Read-only reconciliation is the default for `scripts/recover-news-captures.mjs`; `--apply` is restricted to the main-branch Actions job.

Each check starts at most two catch-up runs, prioritizing the most overdue captures. It preserves each source's current cadence (TradingView 15 minutes; Moneycontrol 30 minutes by day/hourly overnight; RSS hourly; company enrichment three-hourly; X/Telegram half-hourly). Recent attempts and every active GitHub status prevent unnecessary dispatches. Failed jobs receive a 30-minute to six-hour recovery cooldown; publisher backoff and the X opt-out are respected. The shared Moneycontrol/RSS write group is not dispatched twice in one check. Unknown GitHub state fails closed; ambiguous dispatch responses are not automatically retried. The report records decisions separately from source coverage, and a successful dispatch does not mean that fresh data has landed.

This catches an individual delayed schedule using other completion events, **not a GitHub-wide outage**. No new independent Cloudflare cron is claimed: the account's free cron slots are already occupied. The existing read-only operational health check remains necessary; GitHub notifications depend on the operator's settings. An independently hosted uptime/alert service is still needed for guaranteed off-platform notification delivery, and none is silently provisioned here. Workflows that create archive PRs still respect CI and review gates.

[GitHub's scheduler](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) and the existing deployment pipeline can delay publication. The public source has a bounded latest-news window and no observed public pagination cursor; rapid news bursts or upstream omissions can still create gaps. Detected gaps stay recorded, not cleared by the next quiet poll. More frequent collection is risk reduction, not a promise that every story has been seen.

Read `data/tradingview-news/latest.json` for published coverage and `data/tradingview-news/tradingview.json` for per-symbol checkpoints, errors and backoff. `node scripts/check-tradingview-news-health.mjs` checks a local snapshot; setting `FILINGS_HEALTH_BASE` reads a deployed snapshot without dispatching anything. A production retry/manual dispatch still requires explicit authorization. Scheduled recovery is automatic.

Tests: `node scripts/verify-tradingview-news.mjs`, `node scripts/verify-continuous-news.mjs`, and `node scripts/verify-news-recovery.mjs`. They use synthetic upstream responses and temporary local data only, including interrupted collection, uncertain dispatch, failed queue inspection and source backoff.
